

## 3. Development Environment

This section outlines the setup process for the EchoMind development environment, ensuring team members can replicate the setup consistently across machines. It includes instructions for setting up a Dockerized environment, Python dependencies, repository structure, and first-run commands, tailored for a student team with limited resources and diverse technical backgrounds.

### Setup Instructions

**Prerequisites**  
To set up the EchoMind development environment, ensure the following are installed:

- **Docker**: Version 20.10 or higher (includes Docker Compose). Install from [docker.com](https://www.docker.com/get-started).
- **Git**: For cloning the repository. Install via [git-scm.com](https://git-scm.com/downloads).
- **Python**: Version 3.10+ (optional for local development outside Docker). Install from [python.org](https://www.python.org/downloads).
- **Text Editor/IDE**: VS Code, PyCharm, or similar for editing code and viewing Markdown files.
- **Hardware**: Minimum 8GB RAM, 20GB free disk space for Docker images and local development. GPU optional for future open-source LLM hosting (e.g., Mixtral 8x22B).

**Step-by-Step Setup**

1. **Clone the Repository**  
    Clone the EchoMind repository to your local machine:
    
    ```bash
    git clone https://github.com/YOUR_ORG/echomind.git
    cd echomind
    ```
    
    > **Note**: Replace `YOUR_ORG` with your team's GitHub organization (e.g., KN Solvro or a SWPS-affiliated repo). If the repo isn't set up yet, create it and initialize with the structure below.
    
2. **Set Up Environment Variables**  
    Create a `.env` file in the echomind root directory to store API keys and configuration:
    
    ```env
    OPENAI_API_KEY=your-openai-key-here
    # Add other keys as needed (e.g., Hugging Face for Mixtral, xAI for Grok 3)
    WHISPER_MODEL=medium
    LANGUAGE=pl
    ```
    
    - Obtain an OpenAI API key from [platform.openai.com](https://platform.openai.com/) for GPT-4o or GPT-4o Mini.
    - For Grok 3, check [x.ai/api](https://x.ai/api) for API access or use the free tier on [x.com/grok.com](https://x.com/grok.com).
    - The `.env` file is ignored by `.gitignore` to protect sensitive keys.
3. **Install Dependencies (Optional for Non-Docker Development)**  
    If working outside Docker (e.g., for debugging), install Python dependencies:
    
    ```bash
    pip install -r requirements.txt
    ```
    
    See Python Requirements below for details.
    
4. **Build the Docker Image**  
    Build the EchoMind Docker image to ensure a consistent environment:
    
    ```bash
    docker build -t echomind .
    ```
    
    This uses the Dockerfile in the repository root, which installs Python, dependencies, and configures the environment.
    
5. **Run the Docker Container**  
    Start the application using Docker Compose for orchestrated services (e.g., LLM, Whisper):
    
    ```bash
    docker-compose up
    ```
    
    Alternatively, run the container directly:
    
    ```bash
    docker run --rm -it --env-file .env echomind
    ```
    
    - The `--rm` flag removes the container after exit to save space.
    - The `--env-file .env` flag loads API keys and settings.
    - The container exposes the app's CLI or Tkinter UI.

**Troubleshooting**

- **Docker Issues**: Ensure Docker Desktop is running (Windows/Mac) or `dockerd` is active (Linux). Check logs with `docker-compose logs`.
- **API Key Errors**: Verify `.env` file syntax and key validity. Test OpenAI API with:
    
    ```bash
    curl https://api.openai.com/v1/models -H "Authorization: Bearer $OPENAI_API_KEY"
    ```
    
- **Port Conflicts**: If port 8000 (default) is in use, edit `docker-compose.yml` to change ports.
- Contact team leads via GitHub Issues or your team's communication channel.

### Python Requirements

The `requirements.txt` file specifies Python dependencies for both Dockerized and local development. Below is the recommended list based on EchoMind's tech stack:

```txt
# Core dependencies
python==3.10
langchain==0.2.0
openai==1.30.0  # For GPT-4o or GPT-4o Mini
whisper==1.1.10  # OpenAI Whisper for speech-to-text
python-dotenv==1.0.0  # For loading .env files
pyaudio==0.2.14  # For microphone input
numpy==1.26.0  # For audio processing

# UI dependencies
tk==0.1.0  # For Tkinter GUI (MVP)

# Optional for future ML evaluation
spacy==3.7.0
scikit-learn==1.5.0
transformers==4.40.0  # For Polish BERT or Mixtral

# Development tools
pytest==8.0.0  # For unit tests
black==24.3.0  # For code formatting
```

**Installation:**

- Docker handles these dependencies automatically via the Dockerfile.
- For local development, run `pip install -r requirements.txt`.
- If using open-source LLMs (e.g., Mixtral 8x22B), add `huggingface_hub` and GPU-specific dependencies (e.g., `torch` with CUDA) if university GPUs are available.

**Notes for Team:**

- Pin versions (e.g., `langchain==0.2.0`) to avoid compatibility issues.
- Add dependencies incrementally (e.g., `transformers` for Stage 2 ML evaluation).
- Test local installs on a few team members' machines to ensure compatibility before relying on Docker.

### Repository Structure

The EchoMind repository follows a modular structure to support the project's components:

```
echomind/
├── app/
│   ├── main.py                 # App entrypoint / UI loop (CLI or Tkinter)
│   ├── speech_to_text.py       # Voice input + Whisper transcription
│   ├── conversation.py         # LangChain + LLM conversation logic
│   ├── evaluation.py           # Active listening evaluator (rule-based/LLM)
│   ├── prompts/                # Prompt templates for LLM personas
│   │   ├── client_persona_1.txt # Example persona prompt
│   │   └── client_persona_2.txt
│   └── config.py               # Environment and runtime settings
├── tests/
│   ├── test_speech_to_text.py  # Unit tests for speech module
│   ├── test_conversation.py    # Unit tests for dialogue manager
│   └── test_evaluation.py      # Unit tests for evaluation engine
├── Dockerfile                  # Docker configuration
├── docker-compose.yml          # Docker Compose for multi-service setup
├── requirements.txt            # Python dependencies
├── .env                        # (Ignored) API keys and settings
├── .gitignore                  # Ignores .env, __pycache__, etc.
└── README.md                   # Project overview and setup guide
```

**Key Notes:**

- **Modularity**: Each module (`speech_to_text.py`, `conversation.py`, etc.) is independent to simplify development and testing.
- **Prompts Directory**: Stores reusable persona templates for LLM-driven client simulation.
- **Tests Directory**: Includes unit tests for core modules to ensure reliability.
- **Git Ignore**: Ensures `.env` and temporary files (e.g., `__pycache__`) are not committed.

**Team Actions:**

- Initialize the repo with this structure if not already done (use `git init` and create files/folders).
- Assign sub-teams to own specific modules (e.g., one for `speech_to_text.py`, another for `conversation.py`).
- Regularly update `.gitignore` as new temporary files (e.g., model weights) are added.

### First Run

To verify the setup, run the EchoMind application for the first time:

```bash
docker-compose up
```

**Expected Behavior:**

- Docker pulls/builds the image, installs dependencies, and starts the app.
- The app initializes the CLI or Tkinter UI, ready to accept microphone input.
- A test prompt is sent to the LLM (e.g., GPT-4o or Grok 3), and a sample response is displayed.

**Example output (CLI):**

```
[EchoMind] Ready to start session. Speak to begin...
[User] Hello, I'm here to practice active listening.
[Client] Hi, I've been feeling a bit stressed lately...
[EchoMind] Transcription: "Hello, I'm here to practice active listening."
[EchoMind] Feedback: Good start! Try paraphrasing the client's stress.
```

**Validation Steps:**

- Ensure Whisper transcribes Polish audio correctly (`LANGUAGE=pl` in `.env`).
- Verify the LLM (e.g., GPT-4o) responds in Polish with the correct persona tone.
- Check that logs are saved (JSON/CSV) in the container's output directory.
- Debug issues using `docker logs <container_id>` or check GitHub Issues for team-reported problems.
