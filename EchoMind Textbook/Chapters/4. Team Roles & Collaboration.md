## Getting Started - It's Easier Than You Think! 🚀

### 1. Join Our Community

- **First step**: Reach out to the team lead on Discord - they'll get you set up with repo access and show you the ropes

### 2. Find Your Perfect Task

- **Browse our project board**: Check out our GitHub Project board - it's like a menu of cool things to work on!
- **Got an idea?**: Create a GitHub issue and assign it to yourself. We love initiative!

### 3. Git Workflow Made Simple

Don't worry if Git feels intimidating at first - here's your step-by-step guide:

**Our Branch Strategy:**

- `main`: Our stable, working version (the "production" branch)
- `dev`: Where we integrate everyone's awesome work
- `dev/your-task-name`: Your personal workspace (e.g., `dev/evaluation-scoring`, `dev/whisper-setup`)

**Your Workflow (Copy & Paste Friendly!):**

```bash
# Get the project
git clone https://github.com/YOUR_ORG/echomind.git

# Create your branch
git checkout -b dev/your-awesome-task-name

# Make your changes, then save them
git commit -m "Add your descriptive message here"

# Share your work
git push origin dev/your-awesome-task-name
```

**Pull Request (PR) Guidelines - We're Here to Help!**

- **Timing is key**: Submit your PR **3-4 weeks before milestones** so we have plenty of time to review and help you polish it
- **Approval deadline**: **2 weeks before milestone** - but don't stress, we'll work with you to get there!
- **What we need** (but we'll help you with all of this):
    - Working, tested code (we have examples in `app/tests/`)
    - Documentation in English (don't worry, it doesn't need to be perfect!)
    - A clear description of what you built

**PR Template (Feel Free to Copy!):**

```markdown
**PR Title**: [Your Name/Task, e.g., Sarah: Implement Whisper Transcription]

**Description**:
- What did you build or change?
- Link to the GitHub issue you worked on
- Any helpful resources or papers you used

**Checklist** (Check off what you've done):
- [ ] Code works and has tests in `app/tests/`
- [ ] Added comments explaining my code
- [ ] Updated documentation in `docs/`
- [ ] Ready for review!

**Milestone**:
- Target: [e.g., Phase 1, Sep 2025]
- Approval deadline: [e.g., Sep 15, 2025]
```

**Review Process - We've Got Your Back:**

- Our leads will review your work within 3-5 days
- If changes are needed, don't worry - it's totally normal! We'll guide you through any improvements
- Team lead PRs get reviewed by tech leads (everyone gets reviewed, even the leads!)

## Standards & Best Practices (Don't Stress - We'll Help!) 📝

### Code Style

- Follow Python PEP 8 (there are tools to help with this!)
- Add tests when you can - check out examples in `testing_qa/unit_tests.md`
- Ask for help if you're unsure!

### Documentation

- Write in English using Markdown (like this document!)
- Update the relevant files in `docs/` folder
- Example update:
    
    ```markdown
    ## Speech Recognition Module- Added Whisper `medium` model for Polish transcription- New functions can be found in `app/speech_to_text.py`- Usage examples included in comments
    ```

## Life Happens - We Understand 🤗

### Need to Step Away?

No problem! Just:

- Let us know what you've completed
- Document where you left off (we'll help with this)
- Give the team lead a heads up on Discord
- If possible, help us find someone to continue your work

### Running Behind Schedule?

**Please reach out early!** We're here to help, not judge. We can:

- Adjust deadlines if needed
- Provide extra support
- Help break down tasks into smaller pieces
- Connect you with a teammate for collaboration

### Inactivity Policy 

- If we don't hear from you 3 weeks before a milestone, we'll check in to see how you're doing
- We might need to reassign tasks if we can't connect by the deadline
- But honestly, just send a quick message if you need more time - we're very understanding!
